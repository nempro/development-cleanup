# Development cleanup

現在の作業で残したworktree・一時物を対象にする。以前からある物や別プロジェクトの探索・削除へ広げない。日常の開発完了時は**監査のみ**。`$development-cleanup`だけで意図が曖昧なら監査にする。「点検だけ」「変更禁止」は、記録ファイルやSTATEの作成も禁止する。

「後片付けを実行」「安全なworktreeを撤去」などの明示指示がある場合だけ整理を実行する。適用される権限・AGENTS・利用可能ツールの制限は維持する。既に許可された安全な処理について確認を繰り返さない。

## 点検

利用者が指定した作業場所、または現在のプロジェクトのcwdからGit rootを検出する。`python -B -X utf8 <このスキルのscripts/cleanup.py>` は引数なしなら読取点検。サブディレクトリやlinked worktreeからも検出できる。Gitが見つからない、複数候補が曖昧、参照先を上書きする環境変数がある場合は推測して別repoへ広げず保留する。スキルの置場からrepoを推測しない。特定のドライブ名やフォルダ構成を要求・作成・移動しない。

- 実repo root・現在のchatの作業場所・branch・HEAD・status・worktree登録を確認する。主checkout、独立clone、通常フォルダ、linked worktree、Codex管理worktreeを区別する。現在のchat自身のworktreeは撤去しない。実行用cwdだけ別の場所へ変更して回避しない。
- 未コミット・未追跡・本体への未統合commit、ignored内の実データ、build/dist/release/acceptance/experiments内の固有成果、販売版・対応ソース・ロールバック版を確認する。cleanや古い日時、フォルダ名だけで不要としない。squash等で未統合に見える履歴は自動で同等扱いしない。
- 稼働プロセス、起動スクリプト・shortcut・自動起動、必要範囲の他プロジェクト参照、他chatの使用・所有状態を調べる。取得不能・アクセス拒否・管理不明を「参照なし」に置き換えない。設定・認証情報・ユーザー本文は報告に出さない。
- **必須保管／整理可能／未確認**に分ける。未確認は保持する。本体1つだけで今回の一時物もなければ「整理不要」と短く報告し、全ドライブ調査や全テストを追加しない。

## 実行

通常worktree・空フォルダの機械的な検査には `scripts/cleanup.py` を使う。既定の`audit`はstdoutへの読取結果だけで、レポートやレビュー票を自動作成しない。実行方法と証拠票は[references/execution.md](references/execution.md)を、撤去する時に読む。

プロセス情報の欠落があれば撤去を保留する。ヘルパーはGit fsmonitorをコマンド単位で無効化し、外部clean/processフィルター設定のあるrepoは保留する。点検のためにそれらを起動したり、元の設定を書き換えて回避したりしない。

通常worktreeは正式な`git worktree remove`だけを使い、branchと履歴を残す。`--force`、`git clean -fdx`、reset、手動でのworktreeディレクトリ削除は禁止。主checkout・独立cloneの一括削除はしない。ignoredをGitで復元できると思わない。

Codex管理対象は利用可能な`list_artifacts`等と所有chatの状態で確認し、正規の`archive_worktree`を優先する。必要なignoredは別途保護する。共有・所有不明・使用中、現在のchat自身、管理APIで扱えないものは保持する。ヘルパーはCodex管理対象を直接撤去しない。

空フォルダは隠し項目・リンク・登録・参照を再確認して非再帰削除だけにする。その他の一時ファイルは、今回自分が作成し、再生成可能で固有成果がないことを確認した正確な個別パスだけを扱う。非空フォルダの再帰削除や名前パターンによる一括削除はしない。リンクはたどらず、リンクと参照先を区別する。

各対象の直前記録とパス・HEADの再確認を行い、問題の対象だけ保留する。撤去後はworktree登録、本体のbranch/HEAD/refs・追跡差分と無関係な未追跡、残す起動先を照合する。変化や削除失敗があれば停止して原因を記録し、強制操作で片付けない。

最終報告は整理不要／整理完了／保留の理由、実施した範囲と検証限界だけを簡潔にする。ファイル保存は依頼で許可された場所だけ。論理容量と実ディスク解放量を区別する。このスキルは常駐処理ではなく、終了時点検は利用者がAGENTS等に追加した指示を読み込んだchatで行う。導入だけで毎回の点検が自動実行されるとは扱わない。
